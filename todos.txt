## Current status

SyLoPy is a proof-language checker with this pipeline:

```text
proof text -> surface parser/AST -> elaboration -> core proof entries -> ProofLogic validation
```

The main parser, set theory, number theory, discrete-mathematics rules, theorem
promotion, and regression corpus are implemented.

## Architecture and correctness invariants

- `ProofContext` owns elaboration-time lexical scope. The kernel's
  `LabelScope` and `DeclarationScope` remain independent validation-time
  authorities. Do not merge these layers.
- Prefer theory-local syntax, declaration recipes, and elaboration into existing
  core forms. Add a kernel primitive only when it represents genuinely new
  logical behavior.
- Facts that a proof relies on must be visible to validation as hypotheses,
  ordinary formulas, or explicit declaration metadata. No separate type or
  elaboration mechanism may independently justify a proof step.
- Universal Generalization, Existential Elimination, Uniqueness, and theorem
  promotion must account for hypotheses and declaration-structure dependencies,
  not merely formula occurrences.
- Substitution and schema rules enforce variable-capture side conditions, and
  so does the name substitution that `Mutatis mutandis`, WLOG's replay and
  theorem citation share (`_UnsafeSubstitution`). Preserve those guards and the
  project's strict matching discipline; do not casually replace side-condition
  checks with alpha-renaming.
- Rule authorization compares the identity/configuration of registered rules,
  not merely Python class or rule name. See [PR #56](https://github.com/axiomtutor/SyLoPy/pull/56)
  and `pytest_tests/test_rule_configuration_identity.py`.

## Current feature status

### Set theory and proof syntax

Implemented: named Pairing, Union, Power Set, and Infinity axiom-citation rules,
which are now the only way to cite those axioms (generic `(Axiom)` is retired, see
below); Union and Power Set instance forms; scoped witness naming with
`Let Y be such a set. (Existence from L)`; general `Set property`; set equality
and subset proofs; unique existence; equality-case WLOG replay; set enumeration,
set-builder notation, bounded quantifiers, and the documented natural-language
set phrases.

Useful regression references: `pytest_tests/test_axiom_citation_rules.py`,
`pytest_tests/test_set_property.py`, `pytest_tests/test_wlog_symmetric_citations.py`,
`pytest_tests/test_wlog_case_blocks.py`, `pytest_tests/test_set_phrase_parsing.py`,
and `pytest_tests/test_set_enumeration_syntax.py`.

Constraints and open decisions:

- **Generic axiom citations (retired):** the four set axioms are cited only by
  their named rules (`Axiom of pairing`, `Axiom of union`, `Axiom of power set`,
  `Axiom of infinity`); restating one with `(Axiom)` is refused, with the name to
  cite instead. The owner approved this on 2026-10-30. It needed a kernel change:
  an empty axiom list meant "any formula may be cited as an axiom", so emptying
  `SET_AXIOMS` alone would have loosened set-theory proofs. A theory can now close
  its axiom list (`TheoryEnvironment.axioms_closed`, carried to
  `ElaboratedEntries`, `Proof` and `ProofValidator`), so that an empty list means
  none; set theory lists no axiom and closes it. A theory with a non-empty list
  needs no flag. `SET_AXIOMS` stays as the four formulas the named rules accept.
  Regression coverage is `pytest_tests/test_closed_axiom_list.py` and
  `tests/testSetTheory/axioms_cited_by_name.txt`; J34 (ChatGPT) red-teams it.
- **Set property:** the membership characterization and an explicitly matching
  instance determine the inference; the checker must not guess the target term.
  Equality as a direct property disjunct is handled in the supported direction.
  An explicit `Substitution` step performs equality replacement; no separate
  equality-substitution mode for `Set property` is planned under the current
  decision ([issue #69](https://github.com/axiomtutor/SyLoPy/issues/69)).
- **Unspecified defining properties:** a set declared without a stated
  membership characterization does not yet have a symbolic property usable by
  `Set property`. Implemented for `Let Y be a set with defining property P. (Declaration)`:
  the declaration requires an already-declared unary predicate `P`, records
  `defining_property=P` in declaration metadata, and generates the ordinary
  `forall u, (In(u, Y) iff P(u))` formula. Pending: exact subproof replay and
  expanded fixture coverage.
- **Declared unary functions:** typed declarations of the form
  `Let f: X -> Y be a unary function. (Declaration)` lower to unary function
  declarations with `domain=X` and `codomain=Y` metadata; both set names must
  already be declared in scope.
- **Set-operation terms:** parser support now includes names such as
  `A union B`, `A intersection B`, `A cross B`, `pair(a, b)`, and
  `the power set of A`; these lower to declared function symbols and ordinary
  function terms rather than hidden kernel operations.
- **Infinity semantics:** the citation-shape rule exists, but the broader
  treatment of finite/infinite sets is not implemented. The intended set I has
  an abstract membership property P; being infinite is a separate property of
  I, not its defining membership condition. Finite means bijective with
  {0, ..., n-1} for a metatheoretic natural number n. Quantifying over those
  Python integers is not object-language quantification, a risk to resolve
  before implementation. The owner approved implementing it on 2026-10-30. A
  bijection is a function, so it follows the declared-function work below.
- **Witnesses:** `Existence from L` names a witness from an existing existential
  through the ordinary scoped declaration path. The axiom citation itself does
  not introduce the witness. The older direct Pairing-witness form remains for
  compatibility but must not be extended to other axioms.

### WLOG

Equality-case replay is implemented ([PR #63](https://github.com/axiomtutor/SyLoPy/pull/63),
with the later replay fixes in [PR #86](https://github.com/axiomtutor/SyLoPy/pull/86)
and [PR #110](https://github.com/axiomtutor/SyLoPy/pull/110)). The cited line must
be a disjunction and the asserted WLOG formula must be one of its disjuncts;
equality alternatives may differ in exactly one constant term. The validator
also accepts arbitrary alternatives that align structurally under a declared,
one-to-one constant-name exchange. It checks the selected case, transforms and revalidates the
rest of the current proof block for every alternative, and remaps citations
without mutating the original proof. Outside citations need a visible counterpart unless exchanging the case
constants leaves the cited fact invariant (up to commutative ordering of
`and`/`or`). Nested case blocks are included.

Equality alternatives differing in one constant term remain supported.
The owner approved arbitrary-property WLOG on 2026-10-30. Replay structurally aligns arbitrary formulas through a one-to-one constant-name
exchange, while `_UnsafeSubstitution` remains the capture/free-variable guard.
Coverage includes three alternatives, a selected disjunct in the middle, and
rejection of undeclared exchange names. Do not weaken negative replay tests.

### Mutatis mutandis

Implemented in three stages (stage 1 [PR #121](https://github.com/axiomtutor/SyLoPy/pull/121);
stages 2 and 3 were approved by the owner on 2026-10-24). The rule repeats the
argument of a derived line after replacing names, and the checker expands and
validates the repeated argument like any other line rather than trusting a new
inference rule. So a wrong alignment can only make it refuse a line, never
accept a false one.

- Stage 1: a name is replaced by a name.
- Stage 2: a name is replaced by a term with no variable in it, so no quantifier
  can capture it. The replacement is simultaneous and a replacement term is not
  replaced again.
- Stage 3: a predicate or function symbol is replaced by another that takes the
  same number of arguments, everywhere it occurs; two may be exchanged. `=`, the
  connectives and the quantifiers are never replaced. There is no table of
  corresponding rules: a rule that reads a relation's declaration reads the new
  relation's, and a rule about one symbol (`Set property` about `In`) refuses
  another predicate.

A single-line citation `B` repeats that line and its attached subproofs; `A to B`
additionally requires a visible counterpart for A, which is checked but not
repeated. The intervening lines are not replayed. A cited line that mentions a
replaced name or symbol is replaced by the earliest visible line that says the
same of the new one.

The argument must be safe to repeat: premises, assumptions, witness lines,
axiom citations, structure declarations, and unsupported justifications are
rejected. Names and symbols are aligned from the source and target statements;
replacements must fit those statements, and citations must remain visible or
have valid counterparts.

The substitution guard belongs to this `Mutatis mutandis` replay path, not to
quantifier-inference rules. The substitution-application path itself rejects
invalid or capture-causing variable substitutions rather than relying only on
`_mm_align` to make bad mappings unreachable: `_substitute_constants_in_term`
and `_substitute_constants_in_formula` refuse a replacement term with a variable
in it (`_UnsafeSubstitution`), as captured where a quantifier around the name
binds the variable and as free anywhere else. `Mutatis mutandis` and the WLOG
replay report it as an ordinary refusal at the line, and a promoted theorem is
not citable at such an instance. Strict binder matching is preserved; there is no
alpha-renaming and no quantifier-inference side condition changed. WLOG shares
the substitution helpers and its valid behavior is unchanged (it replaces a name
by a name). No proof text reaches the guard, so
`pytest_tests/test_substitution_guard.py` calls it directly and with `_mm_align`
(or WLOG's substitution) taken away. Details and examples are in
[`docs/PROOF_FILE_FORMAT.md`](https://github.com/axiomtutor/SyLoPy/blob/master/docs/PROOF_FILE_FORMAT.md),
`pytest_tests/test_mutatis_mutandis.py`, and
`pytest_tests/test_mutatis_mutandis_reasons.py`.

Not supported, and neither designed nor approved: replacing a compound term as a
whole; repeating a closed block of several lines, so the second case of a proof
by cases cannot be written by repeating the first (11 of the 13 Disjunction
Elimination lines in the corpus have two blocks of the same shape); and
counterpart lines that differ by the symmetry of `=` or `<->`. Do not implement
these without an owner decision.

### Number theory and discrete mathematics

- Number theory deliberately supplies only its documented arithmetic laws.
  Check the header of `source/NumberTheory.py` and [issue #98](https://github.com/axiomtutor/SyLoPy/issues/98)
  before writing a proof that appears to require another law. Do not add axioms
  as part of an example-writing task.
- A relation on X is a subset of X × X (owner decisions, 2026-10-29, which settled
  [issue #136](https://github.com/axiomtutor/SyLoPy/issues/136) as no defect and
  made the subset a fact of the declaration). `Let R be a relation on X` states
  `forall x, forall y, (R(x, y) -> (In(x, X) and In(y, X)))` as a formula of its
  line, as sugar (`DiscreteMath.relation_subset_formula`), so `In(a, X)` follows
  from `R(a, b)` by Universal Instantiation, Universal Modus Ponens and
  Conjunction Elimination (`tests/testDiscreteMath/relation_subset.txt`,
  `pytest_tests/test_relation_subset_sugar.py`). The rules that start from a
  fact `R(a, b)` (symmetry, antisymmetry, asymmetry, transitivity) read only the
  declared property and take no membership premise; the rules that start from
  membership (reflexivity, irreflexivity, totality) require the declared
  carrier. `pytest_tests/test_relation_subset_semantics.py` pins which is which.
  Known costs: declaration bundles and Mutatis mutandis messages are longer, and
  repeating an argument that cites a relation declaration for another relation
  needs that relation on the same carrier. A Universal Modus Ponens over two
  variables at once would shorten the derivation; nobody has asked for it. The
  formula is the predicate-language reading of `R ⊆ X × X`: there are no pair
  terms below). Relation-subset red-team coverage and informational examples are
  available in the corresponding fixture and pytest modules.
- Relation declarations and their property/carrier metadata respect nested and
  sibling proof scopes. Regression coverage: `pytest_tests/test_relation_scope_rules.py`
  and `pytest_tests/test_rule_context_declarations.py`.
- Typed declarations such as `Let n be a natural number` add the corresponding
  ordinary formula (`Nat(n)`); they are not refinement-type checking and do not
  infer arbitrary type facts.

### Theorems and promotion

Theorem promotion carries hypotheses, required nonstandard rules, and required
axioms from the checked proof. An explicit conclusion must be derived at top
level; generalized names must be declared at top level; structural declaration
facts not stated by formulas cannot silently become theorem assumptions.
Premise-carrying theorems can be cited from proof text by title and premise
lines. See `pytest_tests/test_hypotheses_and_promotion.py`,
`pytest_tests/test_promotion_requirements.py`,
`pytest_tests/test_rule_configuration_identity.py`, and
`pytest_tests/test_theorem_surface_citations.py`.

Passing adversarial audits are marked `extended` and excluded from the default
pytest and fixture runner. Run them explicitly with `pytest --extended`,
`pytest -m extended`, or `./run_tests.sh --extended`.

Uniqueness's arbitrary object c and equality target d must be distinct
constants; c must be genuinely arbitrary, absent from the existence line and
from every hypothesis in force, and not constrained by declaration metadata.
The rule explains refusals through those conditions. Regression coverage is in
`pytest_tests/test_uniqueness_rule.py` and
`tests/testProofs/uniqueness_red_team.txt`.

Two policy/design questions were explained to the owner on 2026-10-30 and
decided on 2026-10-31 (the owner agreed with both recommendations):

- A witness named by a top-level `Existence from L` line is not a default
  generalized parameter. It is a fixed existential witness; its defining
  formula remains a premise in the promoted theorem. Ordinary top-level object
  declarations still generalize by default. Implemented and tested by
  `test_existence_witness_is_not_a_default_generalized_parameter`.
- Promoting theorems over declared relation symbols (for example, a theorem about
  any equivalence relation) needs predicate-symbol generalization and a way to
  require matching properties/carrier on the citing declaration. That capability
  does not exist yet; the related theorem is checked but not promoted. Decided:
  yes, after the declared-function work (item 3 of the owner decisions below). The
  route that fits the sugar principle: have declarations state a relation's
  properties as formulas, as they now state `R ⊆ X × X`, so a promoted theorem
  carries them as premises, and generalize over the relation symbol. The same
  mechanism is what "any group" needs later.

## Remaining work

These are directions, not an automatically authorized feature queue. Prefer
small, independently testable increments; check the current issues, PRs, and
collaboration handoff before starting.

1. **Grow examples and regression coverage.** Continue adding useful informational
   proof patterns, especially algebraic and order-theoretic examples, without
   duplicating existing fixtures or changing expected results to hide failures.
2. **Use theory-local extension points.** New syntax and mathematical structures
   should use theory environments, phrase parsers, declaration recipes, rules,
   and focused examples rather than generic parser/elaboration special cases.
3. **Keep the public API and docs aligned.** The README documents the recommended
   API and how to run the proof corpus; update it and `docs/PROOF_FILE_FORMAT.md`
   alongside user-visible changes.

## Contributor workflow

- Run `./run_tests.sh`; use `./run_tests.sh --list-suites` to discover suites
  and `./run_tests.sh --suite NAME --verbose` to focus a run.
- Add parser expectations to `parse_oracle/` with the intended plain-logic
  reading written independently of the parser. Keep malformed-input rejection
  cases.
- The enforced proof fixtures are the correctness floor. Informational fixtures
  need a corresponding pytest test that reports every unexpected result.
- A negative proof must be refused for the condition named by its title, not
  because of a parsing, declaration, or scope mistake.
- Report the tested commit and actual CI results. Do not claim test totals,
  coverage, or fixture counts from an uninspected run.
